# Score Transposer 2.0

## 第一階段：多頁基礎與可靠匯入

- 本機已修復測試 PDF 與原稿圖片；原稿資產的 GitHub 更新尚待明確授權。repo 既有的這兩個檔案仍不完整。PDF worker 改為建置時產生。
- 啟動／建立網頁前，自動從已鎖定版本的 PDF.js 複製 worker。
- PDF 原稿逐頁預覽，最多 20 頁、15 MB。
- MusicXML 保存原稿頁碼，修正小節時顯示來源頁碼。
- PDF 依完整譜行分頁，避免整首縮在一頁。
- 本機辨識以整份文件處理；頁數不符或產生多首分離結果時明確拒絕，不靜默漏頁。
- 中途轉調、拍號變更、時間偏移等尚未支援的內容明確拒絕。

## 後續階段

本階段驗證：14 種調性移調、MusicXML 往返、36 組橫杠、調號省略與跨頁頁碼測試通過；正式網頁建置與 TypeScript 檢查通過。將測試 PDF 重複為兩頁，實際本機辨識回傳兩頁 52 小節，與人工校正版的預期 54 小節不同。因此確認的是多頁流程可運作，並非自動辨識完全準確。尚未進行瀏覽器互動與下載 PDF 的人工驗收。

1. 辨識工作佇列、可取消的進度、逐頁校對紀錄與重新辨識。
2. 收集經授權的多頁測試譜，比對實際漏音、和弦、歌詞及跨頁延音。
3. 簡譜資料模型與辨識；目前尚未支援簡譜。

## 執行

需要 Node.js 22.13+、pnpm、Python 3，以及本機 Audiveris。

```sh
pnpm install --frozen-lockfile
pnpm build
python3 -m venv .venv
.venv/bin/python -m pip install -r local/requirements.txt
```

Mac Audiveris 的 Contents 目錄可由 `AUDIVERIS_HOME` 指定；語言資料目錄由 `TESSDATA_PREFIX` 指定。需安裝 eng 與 chi_tra traineddata。預設位置為 `local/engine/Audiveris.app/Contents` 和 `local/engine/tessdata`。辨識引擎未納入 Git；尚未完成跨平台一鍵安裝。

完成設定後執行 `啟動樂譜工具.command`。開發網頁可使用 `pnpm dev`。網頁建置與測試不需要辨識引擎；任意掃描譜辨識需要引擎。

一般使用不呼叫任何 LLM API。辨識準確度需要逐譜人工核對；人工校正版測試譜不代表自動辨識準確率。
