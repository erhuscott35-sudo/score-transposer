# Score Transposer 2.0

## 第一階段：多頁基礎與可靠匯入

- 已取得使用者明確授權，修復並同步測試 PDF 與原稿圖片到 GitHub，逐一核對檔案雜湊確認傳輸完整。PDF worker 改為建置時產生。
- 啟動／建立網頁前，自動從已鎖定版本的 PDF.js 複製 worker。
- PDF 原稿逐頁預覽，最多 20 頁、15 MB。
- MusicXML 保存原稿頁碼，修正小節時顯示來源頁碼。
- PDF 依完整譜行分頁，避免整首縮在一頁。
- 本機辨識以整份文件處理；頁數不符或產生多首分離結果時明確拒絕，不靜默漏頁。
- 中途轉調、拍號變更、時間偏移等尚未支援的內容明確拒絕。

## 第二階段：辨識工作與逐頁校對（2026-10-10）

- 本機 API v3：建立工作、輪詢狀態、取消工作，顯示實際階段與經過秒數，不虛構辨識百分比或準確率。
- 取消會停止本機 Audiveris 程序並清理暫存，再釋放工作名額。一次處理一份；忙碌時明確提示，不提供排隊功能。
- 工作結果最多保留 8 份，完成 10 分鐘後查詢會過期；發生錯誤或取消後可重新上傳。
- 逐頁勾選核對，顯示小節範圍，可直接跳到原稿頁與小節編輯器。全部頁面核對且節奏檢查通過後才能下載 PDF。
- 頁面資料變更會使該頁核對失效；跨頁邊界音符變更會讓相鄰頁重新核對。核對紀錄僅存在本次瀏覽器工作，重新整理後不保留。
- PDF 分頁邏輯抽出驗證，確保完整譜行不跨頁、不超出頁面。
- 更新後必須重新啟動本機辨識器；舊版 API 會顯示更新提示。
- 修正原稿分頁隱藏時重新排譜導致 SVG 高度為零的問題；回到移調預覽、排譜完成後才開放 PDF。
- 修正側欄過高時下載按鈕無法捲動到的問題。

驗證：Python 取消／真正子程序停止／重試／逾時／結果容量測試通過；已用本機 Audiveris 與 HTTP API 驗證取消及重試。14 種調性、MusicXML 往返、橫杠、升降記號、跨頁校對失效、分頁及前端取消競態測試通過。

## 執行

需要 Node.js 22.13+、pnpm、Python 3，以及本機 Audiveris。

```sh
pnpm install --frozen-lockfile
pnpm build
python3 -m venv .venv
.venv/bin/python -m pip install -r local/requirements.txt
```

Mac Audiveris 的 Contents 目錄可由 `AUDIVERIS_HOME` 指定；語言資料目錄由 `TESSDATA_PREFIX` 指定。需安裝 eng 與 chi_tra traineddata。預設位置為 `local/engine/Audiveris.app/Contents` 和 `local/engine/tessdata`。辨識引擎未納入 Git；尚未完成跨平台一鍵安裝。

完成設定後執行 `啟動樂譜工具.command`。開發網頁可使用 `pnpm dev`。網頁建置與測試不需要辨識引擎；任意掃描譜辨識需要引擎。

一般使用不呼叫任何 LLM API。辨識準確度需要逐譜人工核對；人工校正版測試譜不代表自動辨識準確率。

## 測試

`pnpm test` 執行音樂與工作流程測試；`python3 -m unittest discover -s tests -p 'test_*.py'` 執行本機工作生命週期測試。

`tests/browser-smoke.mjs` 為可重跑的瀏覽器流程測試，需另有 Playwright、Chrome 與運行中的本機網頁，以及 `test-output/two-pages.pdf` 兩頁測試輸入。它使用受控辨識回應測試前端，不能當成辨識準確度證據。本次環境的獨立 Chrome 測試程序無法啟動，改用內建瀏覽器直接操作驗證。
